What this shows




Identity, not network location. The workload's identity is a SPIFFE ID in the certificate's URI SAN. A caller with no certificate, or one signed by a different CA, is refused in the handshake no matter where it connects from.


Authentication is not authorization. The batch identity has a perfectly valid certificate and still gets 403 everywhere until a rule names it. Policy is default deny and keyed on the verified identity, method and path.


Short-lived credentials. Certificates carry a lifetime; an expired one is rejected, and rotation swaps the certificate for new connections with no restart. Revocation by identity blocks a certificate that is still within its lifetime.


Not covered: a real CA and key storage (the root key lives in memory), certificate revocation lists or OCSP, SPIFFE Workload API and attestation, a sidecar proxy, network policy, and any performance testing.
